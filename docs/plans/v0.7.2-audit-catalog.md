## What the step 1 evidence was worth here

- **R8 `-printusage`:** the 107 function names listed for `core:catalog`, `core:network`, `feature:catalog` and `core:data` `catalog.*` were grepped by bare name across main: 106 have a caller, the 107th (`CatalogViewModel.annotations`) is a Kotlin synthetic. A bare-name grep can't separate namesakes (`parse`, `resolve`, `text`, `of`, …), so this only shows that **no listed entry is clearly dead**; the uncommon names were checked by receiver (`kindsSince`, `countryCode`, `normalisedName`, `weighed`, `ShopSession.resolve`, …) and all are called. The removed classes, the truncated „+11"/„+46" entries and the `core:database` entries were not checked one by one; the removed classes seen are inlined value holders, merged interfaces or files of inlined functions. **No dead code was found through R8 in this group.**
- **Lint:** 0 unused resources (evidence §2); the duplicated strings below are *used* twice, which Lint doesn't report.
- **Dependency Analysis:** the `feature:catalog` rows (`ui-tooling-preview`, `navigation-compose`, Roborazzi) come from the convention plugins (`build-logic`), and the `implementation → api` rows describe the module graph of 06 §3; neither is a catalog finding.
- **Largest files** (§4) and **fixtures** (§5): useful, see CAT-A-05 and CAT-A-07.
- A name-only usage script (outside the repository) found only the Hilt modules and two test-only members; it cannot see dead code hidden by a namesake, so the reading above, not the script, is the evidence.
