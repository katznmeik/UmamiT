## What the step 1 evidence was worth here

- **R8 `-printusage`:** every in-scope entry was checked by grep. Of the 107 function names listed for `core:catalog`, `core:network`, `feature:catalog` and `core:data` `catalog.*`, **106 have callers in main**; the 107th (`CatalogViewModel.annotations`) is a Kotlin synthetic. The removed classes are inlined value holders (`BrewInfo`, `DerivedRecipes`, `ResolvedGuide`, …), merged interfaces (`CatalogRepository`, `TeaLinkLoader`, …) or files whose functions were all inlined (`GuideViewModelsKt`, `ShopInterceptorsKt`). **R8 found no dead code in this group.**
- **Lint:** 0 unused resources (evidence §2); the duplicated strings below are *used* twice, which Lint doesn't report.
- **Dependency Analysis:** the `feature:catalog` rows (`ui-tooling-preview`, `navigation-compose`, Roborazzi) come from the convention plugins (`build-logic`), and the `implementation → api` rows describe the module graph of 06 §3; neither is a catalog finding.
- **Largest files** (§4) and **fixtures** (§5): useful, see CAT-A-05 and CAT-A-07.
- A name-only usage script (outside the repository) found only the Hilt modules and two test-only members; it cannot see dead code hidden by a namesake, so the reading above, not the script, is the evidence.

## Checked and left out

- **`ShopSession.isAllowed`** (`ShopSession.kt:55`): looked unused, but `CatalogRefresher.kt:454,514`, `:600` and `CatalogGuides.kt:182` call it.
- **`CatalogDao.refreshLog`** (`CatalogDao.kt:170`): no main caller, but 8 test files read the log through it; a Room query can't move to the test sources, and removing it would weaken those tests.
- **The `@Inject` secondary constructors** (`CatalogRefresher.kt:128–155`, `ShopExactPrices`, `ShopTeaLinkLoader`, `AppCatalogRefreshRunner`): test seams for dispatchers, limits and fakes that Dagger cannot provide without new qualifiers. Kept.
- **Stop-cause mappings** (`CatalogRefresher.kt:357`, `TeaLinkLoader.kt:382`, `SeedPhotoDownloader`) and the **status-code sets** (`CatalogRefresher.kt:986/989`, `ShopSession.kt:95–96`, `ShopResponse.kt:51–55`): each maps to its own result type or rule; merging saves little and touches rule 7.
- **`core:network`** otherwise: small and rule-bound; no other finding.
- **`OwnedCatalogKeys.observe` / `observeOwned`**: two different queries (linked vs owned teas), not a duplicate.
- **Style points left out:** the repeated `log()` helper (`diagnostics.append(clock.nowMs(), clock.zone(), …)`, 4×), `STOP_TIMEOUT_MS` per view model, `showAll` vs `resetFilters` (different meanings).
