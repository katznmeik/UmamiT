# Motion review: v0.5.1 changes (commit 75e4198b, feature/home, feature/catalog, feature/collection)

Read-only review against `docs/specs/03-ux-ui.md` §3.6 (tokens in `UmamiMotion`), D-041 (calm, functional motion
only) and D-055 (reduce motion = every animation ends on its first frame), with the `/review-animations` standards
translated to Compose. Scope: Start's *Zuletzt gebrüht* list (`HomeScreen.kt`, `HomeViewModel.kt`), the catalog
filter sheet (`CatalogFilterSheet.kt`) and the *Knapp ab* field (`TeaDetailStockWarning.kt`). No timer engine or
controller code is touched or proposed (rule 8). The commit adds no `animate*`, `tween` or `spring` anywhere.
Findings already answered in v0.4.1 / v0.5.0 are not repeated, except where this commit changes their weight (S1).

Totals: must 0, should 1, nit 2. Section 2 lists what should NOT animate.

---

## 1. Findings

### S1. should: *Fertig* is now the main way to close the filter sheet, and it still removes the sheet without an exit
- `CatalogFilterSheet.kt:75` (`TextButton(onClick = onDismissRequest)`) with the host at `CatalogScreen.kt:268-274`
  (`onDismissRequest = { filterSheetOpen = false }`).
- Problem: this is the v0.4.1 S1 pattern. The sheet slides in (`rememberCatalogSheetState` starts `Hidden`), but
  *Fertig* calls the host's `onDismissRequest` directly, so the `ModalBottomSheet` leaves composition in that
  frame, with no slide and no scrim fade. Drag and scrim taps do slide out, because Material runs `hide()` first.
  v0.5.0 left it as out of scope because *Fertig* sat at the end of a long list. D-110 moves it into a pinned title
  row, so it is now the first thing a hand reaches for, from any scroll position, and the filter sheet is opened
  often (several times a week). The same sheet leaving two ways is the inconsistency; the missing exit is the
  defect. `TeaDetailPurchaseSheet.kt:74-79` already has the fix pattern in this codebase (`leave`).
- Fix (no new token; Material's own sheet motion, D-051 note in 03 §4; reduce motion skips the slide):
  ```kotlin
  val reduceMotion = UmamiTheme.reduceMotion
  val sheetState = rememberCatalogSheetState(reduceMotion)
  val scope = rememberCoroutineScope()
  var leaving by remember { mutableStateOf(false) }
  val leave = {
      if (!leaving) {
          leaving = true
          scope.launch { if (!reduceMotion) sheetState.hide() }.invokeOnCompletion { onDismissRequest() }
      }
  }
  ModalBottomSheet(onDismissRequest = onDismissRequest, sheetState = sheetState, ...) {
      ...
      TextButton(onClick = leave) { Text(stringResource(R.string.catalog_filter_done)) }
  ```
  `onFilterChange` is untouched, so the filter is already applied before the slide starts. The alert gate stays
  as is: `CatalogScreen.kt:250` and `:268` still remove the sheet in the first frame of an alert, with no exit
  (rule 8). `leaving` stops a double tap from calling `hide()` twice. Add a Robolectric test that *Fertig* ends with
  `filterSheetOpen == false` (under reduce motion at once). Fix `StockSheet` (`core/ui/.../StockSheet.kt`) in the
  same change only if v0.4.1 S1 left it open; check before touching it.

### N1. nit: the pinned title row has no cue that the groups scroll under it
- `CatalogFilterSheet.kt:60-76` (header `Row`) and `:77-83` (scrolling `Column` with `rememberScrollState()`).
- Problem: header and content share the `surface` colour. When the groups are scrolled, chips slide up to the
  header's lower edge and are clipped by the scroll container with no seam, so the header looks cut rather than
  pinned. This is a static-design point more than motion; it only matters because the reason to pin the row is
  that content moves under it.
- Fix (optional, only if the PO notices on the device): hoist `val scroll = rememberScrollState()` and draw a
  `HorizontalDivider(modifier = Modifier.graphicsLayer { alpha = dividerAlpha })` between header and `Column`,
  with `val dividerAlpha by animateFloatAsState(if (scroll.canScrollBackward) 1f else 0f, UmamiTheme.motion.fade())`.
  `fade()` is the existing 300 ms colour/opacity token (100 ms linear under the in-app reduce-motion path, and
  at animator scale 0 Compose ends it on its first frame); the divider is opacity-only and runs on the draw phase
  (`graphicsLayer`, no recomposition per frame). Read `canScrollBackward` through `derivedStateOf` is not needed:
  it is a snapshot state read inside `animateFloatAsState`'s target, which recomposes only on the boolean flip.
  A plain always-visible 1 dp `outlineVariant` hairline is also acceptable and has no motion at all.

### N2. nit: *Zuletzt gebrüht* rows have no `key`, so a reorder re-targets each position's photo painter
- `HomeScreen.kt:172-183` (`state.recent.forEachIndexed { i, brew -> TeaListItem(... rememberPhotoPainter(brew.photoPath)) }`).
- Problem: the rows live in a plain `Column` and are identified by position. After a brew the tea moves to
  position 0 and the others shift down one. Each position's `rememberAsyncImagePainter` then gets a new model, so
  its thumbnail goes back to the leaf placeholder and crossfades in again (200 ms, `photoRequest`), six times, for a
  list that merely reordered. The reorder normally happens while Start is off screen (the brew route is on top, so
  Start is recomposed fresh when it returns, with the same crossfade as any first show); the risk is therefore
  small and the case is mostly a returning-from-brew flicker of six thumbnails, not a visible shuffle.
- Fix (hygiene, one line): wrap the row body in `key(brew.teaId) { ... }` inside `forEachIndexed`, so the painter
  state follows the tea. Do not add `animateItem`: see section 2.

## 2. Rejected: these must NOT animate

| Candidate | Reason |
|---|---|
| Rows of *Zuletzt gebrüht* appearing, leaving or reordering (a tea is brewed, or removed from the collection) | The list is a plain `Column` inside `ScreenScaffold`'s `verticalScroll`, not a `LazyColumn`, so `animateItem` is not available, and wrapping it would only add `AnimatedVisibility` plus `animateContentSize` on a scrolling page, which moves *Favoriten* under a finger. The changes happen with Start off screen (brewing leaves the route; removal happens on the tea's screen), or are a single swap on the next frame. A snap is the calm, correct state change. The spec's functional-motion list (03 §3.6) does not include list content. |
| The count going from three to six rows, or the section filling up over time | Data growth, not an event; occurs once per new tea and never under the user's eye. |
| The empty state ↔ list switch (`empty = state.collectionEmpty`, `HomeScreen.kt:101`) | Happens when the first tea is added from another tab (hidden by `tabSwitch`) or when the last is removed elsewhere. No transition worth its code. |
| Row tap (`TeaListItem` `clickable`, `onClickLabel`) | Spec token `press` is for pills and cards, "not list rows, which keep only the ripple" (03 §3.6). The ripple answers at touch-down. A row now starts a timer, but the next thing the user sees is the timer route itself (route transition, existing). Do not add a scale to the row. |
| A pending state on the tapped row while `starting` is true (`HomeViewModel.kt:217-230`) | The start is a local Room write plus a route change in tens of milliseconds, and the second tap is silently ignored by design (#54 S6). A spinner or dim would flash for one frame. |
| *Knapp ab* text colour (`onSurfaceVariant` while the global value shows, `onSurface` for the tea's own; `TeaDetailStockWarning.kt:53,113`) | See section 3. The swap is a focus or commit state change on a number, the digits do not change (the placeholder shows the same global value), and Material's own label and outline animations already carry the focus change. Animating the text colour in a 3 digit field adds a flicker, not meaning. |
| Pinned header: any collapse, parallax or elevation animation on scroll | A fixed title row with one text button needs none; see N1 for the only optional cue. |

## 3. Checked and fine

- **Knapp ab (`TeaDetailStockWarning.kt:45-114`):** `showsGlobal = text.isEmpty() && !focused` swaps the field
  value between the global number and an empty string, and the quieter colour only applies while unfocused. On
  focus the field shows the empty value with the global number as placeholder in Material's placeholder colour
  (`onSurfaceVariant`), so the digits stay put and only the caret appears: no visible jump. The label starts floated
  (value is never empty while unfocused), so there is no label glide on first composition, which would have been the
  risk. On blur with an emptied field the value returns without animation while the label stays floated: no
  motion needed. The colour switch is a direct parameter, not an animation; that is fine for the reason in
  section 2. Reduce motion: unaffected (no animation involved).
- **Filter sheet pinned header:** Header `Row` and scrolling `Column` are siblings in the sheet's content column, so
  the header does not scroll and does not take part in the sheet's nested scroll; dragging the header or the
  handle still moves the sheet, and dragging the list at scroll offset 0 hands the overscroll to the sheet's nested
  scroll as before (Material's connection is on the `ModalBottomSheet` content, not on the old inner `Column`).
  `navigationBarsPadding()` sits inside the scrolling column, so the last group clears the gesture bar when
  scrolled to the end; no layout change when the header becomes pinned beyond its own height (the old title sat
  at the top of the same content).
- **Sheet entrance and reduce motion:** `rememberCatalogSheetState(UmamiTheme.reduceMotion)` is unchanged, starting
  `Hidden` normally and `Expanded` under reduce motion, so the slide-in is Material's own and ends on its first
  frame at animator scale 0 (D-055).
- **Alert gate:** the filter sheet is still composed only while `!alerting` and `filterSheetOpen` is reset in an
  alert's first frame (`CatalogScreen.kt:250,268`); nothing in this commit softens an alert.
- **Brew start from the list:** `HomeViewModel.brewAgain` keeps the in-flight guard and the double-tap window; the
  row uses the same action as the old tile, so the TMR-21 question and the route change are unchanged. Timer files
  are not part of the commit.
- **Font swap (Alegreya Sans):** a theme resource change; no motion impact, and no text-size animation exists in
  the reviewed files.
- Hover and pointer gating: not applicable (touch only).
