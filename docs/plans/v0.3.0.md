## Process (as in v0.2.2)

- **PR:** one PR from `claude/umamit-m1-start-k0jg3n` into `main`, a draft while tickets are open, using `.github/pull_request_template.md`.
- **Implementers:** subagents in worktrees, with `model` and `effort` per tier (CLAUDE.md rule 5). Brief them with pointers (ticket, spec sections, D-098), not copies. Escalate one tier after a failure.
- **Before merging a ticket:** verify it yourself on the combined tree with the gate below and read the diff. A subagent's report is not proof.
- **Timer tickets:** the 04 §12 tests must pass and are extended per ticket; for #134 the seeded invariant test covers two slots with arbitration.
- **Code review at the end:** T4 for the timer, the alert player and the migration, T3 for the rest; fix or answer every finding.
- **Reporting:** push notifications only when the PO must act (rc ready, a blocking question). Questions go to the PO as selectable options.

## Local gate

As for v0.2.2, in sequential parts:

```bash
export ANDROID_HOME=${ANDROID_HOME:-/opt/android-sdk}
./gradlew spotlessCheck detekt checkManifestPermissions
./gradlew --max-workers=1 testDebugUnitTest
./gradlew --max-workers=1 lint
./gradlew --max-workers=1 verifyRoborazziDebug
./gradlew assembleDebugAndroidTest
```

- **A part killed for memory** (exit 137) is not a test failure: rerun that part alone.
- **At most two Gradle builds at once** across the orchestrator and the implementers. The container restarted on 2026-10-30 when more ran; an implementer waits rather than start a third.
- **Stopping Gradle:** never use `pkill java`, which kills every daemon including the agents'. Stop your own daemon with `./gradlew --stop`.
- **Robolectric's runtime jar** is fetched at test time, and a network hiccup has failed CI twice. Rerun once and comment on the PR.

## Guards that bite in this release

- **Frozen schemas:** `umamit.db` v1, v2 and v3 and `catalog.db` v1 are frozen by the `v*` tags. #126 adds v4 next to them; `scripts/check-frozen-schemas.sh` compares bytes. Never edit v1–v3.
- **Migration:** a timer running, waiting or alerting during the update keeps its state and alerts on time; one transaction; never destructive (05 §9).
- **Accuracy run, both variants:** every rc and the final release need a PASS of the standard run **and** `alongside` on their commit (full SHA, `api-level` 36, `steps` 50, `inject-delay-ms` 0; about 1 h each). Targets p95 ≤ 250 ms and max ≤ 1000 ms, for both timers in `alongside`. Prove the gate once after the workflow change with `inject-delay-ms: 1500` (09 §4a).
- **Rule 8:** nothing may delay, hide or silence an alarm. A held quick alert always rings; the brew alarm never waits; never two sounds at once; the alert stays the app's only notification of importance DEFAULT or higher (D-044).
- **Manifest:** WorkManager adds `ACCESS_NETWORK_STATE`; remove it (`tools:node="remove"`) so `checkManifestPermissions` stays green, or record it in 06 §5.7 first.
- **No downgrades:** going back to v0.2.2 needs an uninstall.
