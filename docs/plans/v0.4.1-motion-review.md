# Motion review: v0.4.1 new/changed screens (diff aa1c110d..HEAD)

Read-only review against `.claude/skills/review-animations` (SKILL.md, STANDARDS.md), translated to Compose, and
`docs/specs/03-ux-ui.md` §3.6 (tokens in `UmamiMotion`, `core/designsystem/.../motion/Motion.kt`).
Nothing in timer code was touched or proposed (rule 8). Every duration below is an existing `UmamiTheme.motion`
token, so reduce motion (animator scale 0, D-055) is honoured for free.

Totals: must 0, should 5, nit 3. Section 2 lists what should NOT animate.

Overall: the diff adds almost no motion code of its own. It leans on Material defaults (pager, dropdown, dialogs,
date pickers, `ModalBottomSheet`), so the risk is in the places where it bypasses them: composition removal of a
sheet, async image pop-in, and state swaps with no transition.

---

## 1. Findings

### S1. should: Purchase sheet snaps shut on *Erfassen* and *Abbrechen* (slides in, does not slide out)
- `feature/collection/.../detail/TeaDetailPurchaseSheet.kt:136,140` (buttons) with `TeaDetailScreen.kt:259-269`
  (host) and `rememberPurchaseSheetState` at `:271-281`.
- Problem: both buttons end in `purchaseSheet.close()`, which removes the `ModalBottomSheet` from composition in
  that frame. It enters with Material's slide (sheet state starts `Hidden`) but leaves with no exit at all. Drag
  and scrim dismissals do slide out, because Material runs `hide()` before `onDismissRequest`. The result is
  asymmetric and inconsistent: the same sheet leaves two ways. Asymmetry should run the other way (system
  response snappy, never absent). Frequency is occasional (a few purchases a month), so a standard 200 ms exit
  is justified. `StockSheet` (`core/ui/.../StockSheet.kt:73`) has the same pattern and was not changed in this
  diff; fix both together or leave both.
- Fix:
  1. In `PurchaseSheet` keep `val sheetState = rememberPurchaseSheetState(...)` and
     `val scope = rememberCoroutineScope()`. Define
     `val hideThen: (() -> Unit) -> Unit = { done -> scope.launch { if (!UmamiTheme.reduceMotion) sheetState.hide() }.invokeOnCompletion { done() } }`
     (the `StepsModalSheet.kt:82` pattern; with reduce motion skip `hide()`, matching spec §4.x "leaves without
     the slide").
  2. *Abbrechen*: `hideThen(onDismissRequest)`.
  3. *Erfassen*: call `onSave(purchase)` at once (the write must not wait), then `hideThen { onDismissRequest() }`.
     In the host, change `onSave` so it only calls `actions.recordPurchase(purchase)` and let the sheet call
     `onDismissRequest` (`purchaseSheet.close()`) after the hide. Set a `var leaving by remember { mutableStateOf(false) }`
     and pass `enabled = purchase != null && !leaving` to the `PillButton` so a second tap cannot record twice.
  4. Keep the alert gate as is: `AlertGated` still removes the sheet in the first frame of an alert (rule 8).
  - Spring/duration: Material's own sheet spring (do not use the `sheet` token here, D-051 note in §4).

### S2. should: photos pop in on load (no placeholder, no fade) on the detail hero, the vessel editor and the Teegeschirr list
- `TeaDetailPhotos.kt:234-244` (`PagerPhoto`), `VesselEditorScreen.kt:432-440` (`PhotoImage`),
  `TeawareScreen.kt:265-274` (`VesselPhotoThumb`); painters from `core/ui/.../PhotoPainter.kt` (`rememberPhotoPainter(path)`,
  `rememberPickedPhotoPainter(uri)`).
- Problem: `rememberAsyncImagePainter(model)` returns a non-null painter at once, so the `painter != null` branch is
  always taken and the `else` placeholder branches are dead for a stored photo. While Coil decodes, the 4:3 hero
  (and the 180 dp vessel field, and the 40 dp thumb) is blank, then the picture appears in one frame. No Coil
  `crossfade` is configured anywhere (grep: none). A hard pop of a large image is the most visible un-animated
  state change in this release; a picked vessel photo (SCR-14) does it right after the picker closes.
- Fix (two parts, both static-safe):
  1. Always draw the tint under the image so the slot never reads as a hole: for the hero page
     `Box(Modifier.fillMaxSize().background(placeholderColor.copy(alpha = PLACEHOLDER_ALPHA)))` behind the `Image`;
     for the vessel field and the thumb `.background(MaterialTheme.colorScheme.surfaceVariant)` before `.clip(...)`/`Image`.
  2. One-shot fade of the image over that tint: build the request with
     `ImageRequest.Builder(LocalContext.current).data(File(path)).crossfade(if (UmamiTheme.reduceMotion) 0 else 200).build()`
     and `rememberAsyncImagePainter(model = request, contentScale = ContentScale.Crop)` (Coil 3 needs the
     `contentScale` for the crossfade to size correctly). 200 ms equals the `exit` token; Coil skips the fade
     for memory-cache hits, so revisits and list scrolls stay instant. Put it in `rememberPhotoPainter` and
     `rememberPickedPhotoPainter` once instead of in the three call sites. Do not change the catalog/list
     thumbnails' behaviour without the PO seeing it: the fade is app-wide once it lives in `PhotoPainter.kt`
     (check Roborazzi goldens, which load synchronously and should be unaffected).

### S3. should: a newly added photo jumps into view with `scrollToPage`
- `TeaDetailPhotos.kt:87-90`.
- Problem: after *+ Foto*, the pager hard-jumps from the page being viewed to the new last page. No spatial cue
  for where the new photo sits (it is appended after the others) and it is the only pager move in the app that
  teleports. The action is user-initiated and rare, so a short, calm travel is appropriate, not a snap.
- Fix: replace `pager.scrollToPage(photos.lastIndex)` with
  `if (pager.currentPage < photos.lastIndex - 1) pager.scrollToPage(photos.lastIndex - 1)` followed by
  `pager.animateScrollToPage(photos.lastIndex, animationSpec = spring(dampingRatio = 1f, stiffness = 320f))`
  (the `sheet` token physics: critically damped, no overshoot). The pre-jump to the second-to-last page keeps the
  travel to one page however many photos there are (and avoids composing a strip of pages). Keep the existing
  guard `shown.intValue > 0` (first photo: nothing to travel). Reduce motion needs no branch: Compose finishes
  the animation on its first frame at animator scale 0. Interruptible by a swipe (scroll mutex), which is right.

### S4. should: pager dots change colour instantly while the page glides
- `TeaDetailPhotos.kt:271-278` (`Dots`).
- Problem: `index == current` flips `onSurface` / `onSurface.copy(alpha = 0.38f)` in one frame, at the swipe's
  midpoint, while the picture is still sliding. Indicators are state feedback; a hard flip reads as a glitch next
  to continuous motion.
- Fix: `val color by animateColorAsState(target, animationSpec = UmamiTheme.motion.exit(), label = "dot")`
  (200 ms `CalmEaseOut`; reduce motion becomes a 100 ms linear fade through `fade()` only if you use `exitFade()`;
  use `UmamiTheme.motion.exitFade()` to match). Do not animate dot size/width (layout), colour only.
  Alternative with more fidelity: lerp each dot from `pager.currentPageOffsetFraction`; not worth the code for a
  6 dp dot.

### S5. should: next photo is composed only after the swipe starts
- `TeaDetailPhotos.kt:96-106` (`HorizontalPager`, default `beyondViewportPageCount = 0`).
- Problem: with S2 the neighbour page starts decoding when it first enters the viewport, so a swipe shows an
  empty tint for several frames (worse on the first swipe after opening the detail). The motion is fine; its
  content is late.
- Fix: `HorizontalPager(..., beyondViewportPageCount = 1)`. Cost: one extra bounded-size bitmap decode (photos are
  transcoded, `PhotoTranscoder`); no animation involved. With S2 in place this makes the swipe look finished.

### N1. nit: Settings is popped inside the outgoing tab while that tab is fading out
- `app/.../UmamitApp.kt:161-164` (`select`), `:796-808` (`leave`, `closeSettings`).
- Problem: `popBackStack<SettingsRoute>(inclusive = true)` runs in the same frame as `selected = tab`. The outgoing
  tab's `NavHost` is still composed for the 90 ms `tabSwitchOut`, so it starts the `popExitTransition` (slide plus
  200 ms fade) and shows the root screen underneath; the `AnimatedContent` exit then disposes it about 45 % in.
  Two motions in one layer, in a fade-through that is meant to show one calm change. Rare (Settings open when the
  tab is switched), under 90 ms, hence nit.
- Fix: close it once the old tab has left. Keep `var leftTab by remember { mutableStateOf<Tab?>(null) }`, set it in
  `select` instead of calling `leave`, and
  `LaunchedEffect(leftTab, transitionState.currentState) { val t = leftTab; if (t != null && transitionState.currentState != t) { controllers.getValue(t).closeSettings(); leftTab = null } }`.
  A hidden tab's controller keeps its back stack, so the pop is invisible. If the user comes back to `t` before the
  effect fires, pop at once (it needs no animation because that tab is not yet visible). Do not use
  `ExitTransition.None` on the pop instead: that would swap Settings for the root in one frame inside the fade.
  If you judge this not worth the extra state, leave it: the current behaviour is harmless.

### N2. nit: *Packung als geöffnet markiert* line changes the sheet height when *Rückgängig* is tapped
- `feature/journal/.../SavedSheet.kt:351-381` (`OpenedUndo`).
- Problem: the `Row` with a `TextButton` (min 40 dp touch height) is replaced by a bare `Text` (about 20 dp). The
  sheet is bottom-anchored, so its top edge drops by about 20 dp at the tap, with no transition. Same pattern as
  the existing `RecipeOk` (`:386-410`), so it is consistent, just a small jump on the confirmation moment.
- Fix (no animation, preferred): give both branches the same minimum height,
  `lineModifier.heightIn(min = 40.dp)` and `verticalAlignment = Alignment.CenterVertically`, so nothing moves.
  Or, if you want a visible acknowledgment, `Crossfade(targetState = done, animationSpec = UmamiTheme.motion.fade())`
  around the two branches, still with the shared minimum height. The sheet's auto-dismiss timer and `liveRegion`
  announce the change for TalkBack already. Do not animate the sheet's height.

### N3. nit: Save and the overflow menu pop into the editor top bar when the form loads
- `core/ui/.../EditorScaffold.kt:67-74`.
- Problem: `if (showActions) { TextButton(Save); menu() }` inserts the actions a frame or two after the route
  transition begins (Room load). During the 300 ms route enter the user can see the top bar gain two controls.
  Moved here from three editors, so it is now the single place to fix.
- Fix (layout-stable, no animation): always compose the Save `TextButton` with
  `enabled = showActions && !saving` and keep `menu()` gated; the label's width does not change. If that breaks
  tests that expect no Save while loading, instead wrap the actions in `AnimatedVisibility(visible = showActions, enter = fadeIn(UmamiTheme.motion.fade()), exit = ExitTransition.None)`
  (opacity only, 300 ms `CalmEaseOut`, reduce motion 100 ms).

## 2. Rejected: these must NOT animate

| Where | Why not |
|---|---|
| Photo ⋮ menu, reset question, delete-photo, delete-entry, `DatePickerDialog`s (`TeaDetailPhotos.kt:163,182`, `TeaDetailScreen.kt:*ResetDialog*`, `TeaDetailHistory.kt:199+`, `TeaEditorInputs.kt` `OptionalDate`, purchase `PurchaseDay`) | Material defaults, same as `DiscardChangesDialog`. Alert-gated removal is deliberate (rule 8). A custom animation here would only add risk to the alert-first guarantee. |
| `AlertGated(...)` removal of dialogs on close | A `Dialog` window has no exit animation when removed from composition; accepted platform behaviour, and the gate's frame-exact removal matters more. |
| History *Alle … Einträge anzeigen* (`TeaDetailHistory.kt:72-92`) | The tapped control is replaced, at the same spot, by the rows it reveals; instant is the clearest outcome. `animateContentSize` would animate height (layout) in a scrolling page and make the following sections slide. |
| Purchase/correction/brew row added or deleted in the history, stock number "38 g übrig" changing | Outcome of an action the user just confirmed in a dialog or sheet; a counting or row-insert animation is decoration. |
| Gram/price error text in `AmountField`, `PurchaseDay` error, `OptionalDate` error/hint | Appears per keystroke (keyboard input, high frequency); never animate. The future-date error is only reachable by midnight rollover. |
| Enabled/disabled of *Erfassen* | Toggles per keystroke; no animation. |
| `OptionalDate` *Entfernen* button appearing and the date button narrowing (`TeaEditorInputs.kt` `Row`) | Happens right after a dialog closes, when attention is not on the field; width animation would be a layout animation. Leave. |
| `FreshnessChip` (`core/designsystem/.../FreshnessChip.kt`) in the detail FRISCHE section, the picker row and wherever else | State label, derived from a date; colours change only when data changes. It must be a word, never colour alone (and no pulse: an animated chip next to the timer would compete with the alert language). Compact picker chip is in a list scrolled many times a day: static. |
| Tea picker chip (`TeaPickerSheet.kt:319-325`) | Part of the row emission, no late pop. No stagger or press motion. |
| FRISCHE section appearing/disappearing | Data-driven, in a scrolling page; instant. |
| Photo delete / *Als Titelbild* in the pager | `HorizontalPager` has no item-placement animation, the key keeps the page from jumping (#186); adding custom motion is not worth the code for a rare action. |
| *+ Foto* disabled state with „Höchstens 10 Fotos" text swap | State label; instant. |
| Vessel editor *Foto hinzufügen / ersetzen / entfernen* swap between tint+icon and image (`VesselEditorScreen.kt:~385-410`) | Covered by S2 only for the image load; the structural swap itself is a result of an explicit tap and stays instant. |
| Teegeschirr list rows (`TeawareScreen.kt`) | Thumb size is fixed at 40 dp for both icon and photo, so nothing shifts; no item-placement or stagger. |
| `EditorScaffold` discard dialog / back handling | Unchanged behaviour; no motion. |
| Reset-from-catalog result (recipes/description replaced) | The user confirmed a destructive dialog; content swap is the feedback. |

## 3. Checked and fine
- Purchase sheet uses the same reduce-motion pattern as `StockSheet`/`StepsModalSheet` (`initialValue = Expanded` when
  reduced, so no slide); only the missing exit (S1) is off.
- `SavedSheet` enter/exit and drag already use `motion.sheet()`, `fade()`, `exitFade()`; the new opened-date content is
  loaded before the sheet is shown (`rememberSavedSheetContent`), so it does not pop in after the slide.
- Tab switch uses `tabSwitchIn/Out` (90 + 210 ms fade-through), correct for a tens-per-day action; not touched.
- No new `animate*`, `tween` or keyframes anywhere in the diff, no `transition: all` analogue, no ease-in, no layout
  property animation, no timer file touched.
- Hover/pointer-gating: not applicable (touch only).
