### Findings

#### A-01 — Start (SCR-02): *Aufguss starten* overlaps the header picture (PO point, D-138 Q11, item 18)
- **Problem:** the picture and the card sit apart (the band's 8 dp bottom padding, then the card), so they read as two things and the block takes 256 dp under the title bar before *Zuletzt aufgegossen*.
- **Proposal:** the picture keeps its 120 dp band; the first card of the block (*Aufguss starten*, or *Aufguss fortsetzen* in the active state, with the cards below it) is pulled up so it overlaps the picture's visible lower edge, and everything below moves up by the same amount (a layout modifier that places the card column at −(8 + overlap) dp and reports its height shorter by as much; drawn after the picture, so on top). Two values to pick from, fixed dp (not scaled with font, so the picture stays visible at font 2.0):
  - **variant a:** overlap **24 dp** ≈ one third of the card's 72 dp → the block moves up 32 dp;
  - **variant b:** overlap **36 dp** ≈ one half → the block moves up 44 dp; the card then covers the lower blossoms.
  - Net effect with A-02's taller card (72 dp instead of the 48 dp text button, plus the 12 dp gap): *Zuletzt aufgegossen* starts 12 dp higher than today in a, 24 dp higher in b (at font 1.0, light).
  - **Gap between the cards: 12 dp** (`UmamiSpacing.Small`), the gap *Aufguss fortsetzen* → *Aufguss starten* already uses; the same 12 dp to the *Schnelltimer* card (A-02). The section header below keeps its 24 dp top padding. Reliability banner stays above the picture, the nudge card below the cards (item 18). Empty state: no picture, so no overlap (A-02 picture). No shadow (flat design, 03 §3.3).
- **Kind:** component/layout
- **Pictures:** A-01_before.png / A-01a_after.png / A-01b_after.png; `_font2` and `_dark` of each (A-01_before_font2.png, A-01a_after_font2.png, A-01b_after_font2.png, A-01_before_dark.png, A-01a_after_dark.png, A-01b_after_dark.png); active session, variant a: A-01a_active_before.png / A-01a_active_after.png. **All after pictures already contain the A-02 card**: the PO judges the block as a whole.
- **Modules/files:** `feature/home/.../HomeScreen.kt` (`BrewCards`, `Header`)  **Tier:** T2  **Timer code:** no
- **Depends on / conflicts with:** rendered together with A-02 (the PO's pick of a or b sets the value in 03 SCR-02)

#### A-02 — Start (SCR-02): *Schnelltimer* as a second, lighter card (PO point, D-138 Q12, item 17)
- **Problem:** *Schnelltimer* is a small text button that leaves an odd 56 dp of air below it and looks like an afterthought next to the card.
- **Proposal:** a full-width card under *Aufguss starten*, the same shape and size: `Surface` with `UmamiShape.PrimaryCard` (12 dp), `colorScheme.surface`, a 1 dp `outline` border (`UmamiSpacing.Hairline`), min height 72 dp, padding 24 dp × 16 dp; the clock icon (`UmamiIcons.Timer`) 32 dp in `primary`; title *Schnelltimer* in `titleLarge` `onSurface`; second line „Nur die Zeit, ohne Tee" / „Just the time, no tea" in `bodyMedium` `onSurfaceVariant`; a plain chevron in `onSurfaceVariant` (no fill). One button for TalkBack (Surface onClick merges). Same `press` scale as `PrimaryActionCard` (0.97, `tween(120, CalmEaseOut)`, release spring) — not visible in a still. 12 dp below the card above it; at font 2.0 both cards grow and stay stacked (A-01a_after_font2.png). In the empty state the card takes the text button's place under the title bar (8 dp top). „Accent colour" for the icon is read as `primary` (#4A5643 light / #B9C8A6 dark): the warm accent #D9A35F would be 1.97:1 on `surface`, below 3:1 for a graphic.
- **Kind:** component/layout
- **Pictures:** in A-01a/A-01b after pictures (light, dark, font 2.0); English: A-02_en_before.png / A-02_en_after.png; empty state: A-02_empty_before.png / A-02_empty_after.png
- **Modules/files:** `feature/home/.../HomeScreen.kt` (replaces `QuickTimerEntry`), `feature/home/src/main/res/values{,-en}/strings.xml` (`home_quick_timer_subtitle`, approved copy)  **Tier:** T2  **Timer code:** no
- **Depends on / conflicts with:** A-01 (one block)

#### A-03 — Neue Session (SCR-04): the selected recipe chip in `primaryContainer`, as 03 §3.1 says
- **Problem:** the selected recipe chip uses M3's default `secondaryContainer`, against 03 §3.1, which assigns `primaryContainer` to selected chips. In dark the cream (#E5DFCF) chip is the brightest thing on the screen and competes with the cream *Session starten* pill; in light the cream reads as a neutral tag rather than a choice.
- **Proposal:** `FilterChipDefaults.filterChipColors(selectedContainerColor = primaryContainer, selectedLabelColor = onPrimaryContainer, selectedLeadingIconColor = onPrimaryContainer)` on the recipe chips (and *Ohne Rezept*). Light: sage #DDE2D2 with ink (a hue shift towards the matcha accent; the fill stays as light as before, the ✓ still carries the state); dark: the generated deep green #2B4F1E with a light-green label, which no longer outshines the start pill. The dark green is noticeably more saturated than the rest of the Steeping palette: the PO should judge the dark picture in particular. No new token. The same default is used by every `FilterChip` in the app (Sammlung, Katalog, Journal filters, Schnelltimer chips): merge with the other groups' chip findings if they make one; this render shows the setup only.
- **Kind:** type/colour
- **Pictures:** A-03_before.png / A-03_after.png; A-03_before_dark.png / A-03_after_dark.png
- **Modules/files:** `feature/brew/.../setup/BrewSetupScreen.kt` (`RecipeChips`)  **Tier:** T3 (feature:brew)  **Timer code:** yes
- **Depends on / conflicts with:** —

### Findings

#### A-40 — Meine Tees (SCR-08) and Katalog (SCR-19): the filter row fades at the edge
- **Problem:** The sideways-scrolling chip row cuts a pill hard at the screen edge (*Kategorie* on Meine Tees, the next kind on Katalog). On Katalog it also cuts *Filter* on the left when a selected kind is revealed (`Catalog_listBlack`).
- **Proposal:** Keep the row's scroll. On each side that has more content, the row fades to transparent over 24 dp at the screen edge, so it fades into whatever background is behind it. The fade is an alpha mask (offscreen layer plus a `DstIn` gradient), and there is no fade on a side where nothing is cut. It is static, with no timed animation. The fade strength follows the scroll offset over the first and last 24 dp, so it thins out as the row reaches either end. Scrolled to its end, the last pill keeps the 20 dp side margin (the row's inner padding, unchanged). Implementation is one shared modifier, `Modifier.horizontalEdgeFade(scrollState, width = 24.dp)`, in `core:ui`, put before `horizontalScroll` on both rows.
- **Kind:** component/layout
- **Pictures:** A-40_before.png / A-40_after.png (+ _font2, _dark); A-40_katalog_before.png / A-40_katalog_after.png (+ _font2, _dark); A-40_end_after.png (Meine Tees scrolled to the end: the left side fades, and *Archiviert* sits 20 dp from the edge with no fade on the right).
- **Modules/files:** core/ui (new `EdgeFade.kt`), feature/collection `MyTeasParts.kt` (`MyTeasChips`), feature/catalog `CatalogFinding.kt` (`CatalogFilterChips`). Re-recording the Collection_* and Catalog_* goldens with a chip row is a mechanical follow-up. The `Catalog_chipRow` golden (2400 dp wide, nothing cut) shows no fade.  **Tier:** T2  **Timer code:** no
- **Depends on / conflicts with:** — (the same modifier fits any other chip row in the app, e.g. the SCR-16 infusion chips)

#### A-41 — Tee (SCR-09): content scrolls under the floating back and ⋮ buttons
- **Problem:** Once the hero scrolls away, there is nothing behind the floating back and ⋮ circles. Text such as „Rezept hinzufügen" runs under them, and while scrolling, the *+ Foto* pill slides under ⋮ and merges with it into one blob that reads „+ Fo⋮o" (`TeaDetail_vorrat`, `_lowArchived`, `_history`, `_taste`). On the device the text also runs under the status bar.
- **Proposal:** Add a strip in `colorScheme.background` behind the two buttons. It covers the status-bar inset plus 64 dp (8 + 48 + 8) and has a 1 dp `outlineVariant` hairline at its bottom. Its opacity is tied to the scroll and ramps 0→1 over 24 dp: it is fully opaque by the time *+ Foto* reaches the strip (hero bottom ≤ 64 + 56 dp from the top), and it is invisible while the hero shows (`TeaDetail_rating`/`_ready` unchanged). The buttons keep their `OverPhoto` circles on top. No timed animation. The same strip applies to SCR-21 Katalog-Tee and SCR-20 Ratgeber-Artikel, which use the same floating back button.
- **Kind:** component/layout
- **Pictures:** A-41_before.png / A-41_after.png (+ _dark)
- **Modules/files:** feature/collection `detail/TeaDetailScreen.kt` (a composable drawn between the scrolling column and `TopActions`), then feature/catalog `CatalogTeaScreen`/Guide article. In the build it is best as one `core:ui` piece beside `PhotoHero`.  **Tier:** T2  **Timer code:** no
- **Depends on / conflicts with:** —

#### A-45 — Tee (SCR-09): the pencil FAB merges with filled buttons
- **Problem:** The pencil FAB is filled `primary`, the same colour as the sticky *Session starten* and the prominent *Beim Tee-Kontor nachbestellen* (*Knapp*/*Leer*). Where they meet while scrolling, FAB and button fuse into one shape (`TeaDetail_lowArchived`). The screen shows three primary-filled shapes. Teegeschirr's FAB is already tonal.
- **Proposal:** Give the pencil FAB `primaryContainer` / `onPrimaryContainer` (the Teegeschirr FAB's colours, measured identical in both themes). No new token. *Session starten* stays the screen's only primary fill. 03 §3.1's `primary` row („FAB") would then read „FAB on Start/…" and lose tea detail. The alternative is to make Teegeschirr's FAB `primary` too, for consistency only, but that leaves the merge.
- **Kind:** type/colour
- **Pictures:** A-45_before.png / A-45_after.png (+ _dark)
- **Modules/files:** feature/collection `detail/TeaDetailScreen.kt` (FloatingActionButton colours); 03 §3.1 table.  **Tier:** T1  **Timer code:** no

#### A-43 — Tee › Vorrat (SCR-09/29): the stacked stock buttons have ragged widths
- **Problem:** In German, *Nachkauf erfassen* (193 dp) and *Bestand korrigieren* (197 dp) never fit side by side, so they stack. Their widths differ by 4 dp and they stop at different points mid-screen, which looks like an error. Below them the reorder link is full-width in its filled form.
- **Proposal:** When the two buttons stack, both span the content width (371 dp at 411 dp). Where they fit side by side (English, wide screens), each takes an equal half with a 12 dp gap. Same outlined style, icons and labels centred. This matches *Im Shop öffnen* (SCR-21) and the full-width filled reorder button.
- **Kind:** component/layout
- **Pictures:** A-43_before.png / A-43_after.png
- **Modules/files:** feature/collection `detail/TeaDetailSections.kt` (`Stock`, the `FlowRow`). For the render, `fillMaxWidth()` was used, which is always stacked. The real build needs the side-by-side half split, either a row with two `weight(1f)` children when both fit at their intrinsic width or a column otherwise. `FlowRow` with `weight` alone squeezes the labels onto two lines, so don't use it.  **Tier:** T2  **Timer code:** no
- **Depends on / conflicts with:** —

#### A-42 — Text-button actions sit inside the content column (SCR-09, SCR-14, SCR-32)
- **Problem:** Standalone text buttons keep M3's 12 dp inner padding but are placed at the 20 dp margin, so their labels start 8–12 dp to the right of every other line on the screen. *Beim Tee-Kontor nachbestellen* and *Alle 7 Einträge anzeigen* start at 32 dp (SCR-09). *Foto hinzufügen* starts at 32 dp (SCR-14). *Anderen Tee wählen …* and *Tee über Shop-Link laden* start at 24 dp (SCR-32).
- **Proposal:** Place these buttons at 20 − 12 = 8 dp, so the label starts on the 20 dp column. The ripple and touch target extend into the margin, which is not content at rest (edge rule unaffected). Keep icon-led buttons as they are where the icon is already at about 20 dp (*Rezept hinzufügen*). Dialog and sheet action buttons are unaffected.
- **Kind:** spacing
- **Pictures:** A-42_before.png / A-42_after.png (Gefäß bearbeiten); A-42_rezept_before.png / A-42_rezept_after.png (Rezept übernehmen). The SCR-09 instances are not rendered separately because the same goldens carry A-41/A-43/A-45. The change there is the same −12 dp.
- **Modules/files:** feature/teaware `VesselEditorScreen.kt` (photo buttons row); feature/collection `receive/ReceiveRecipeScreen.kt` (*Anderen Tee wählen*, `ShopLink`); `detail/TeaDetailSections.kt` (reorder link); `detail/TeaDetailHistory.kt` (*Alle N Einträge anzeigen*).  **Tier:** T1  **Timer code:** no
- **Depends on / conflicts with:** — (touches the same SCR-09 section as A-43, but the two are independent)
