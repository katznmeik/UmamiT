## Checked and left out

- **The four editor view models** (`TeaEditorViewModel`, `RecipeEditorViewModel`, `VesselEditorViewModel`, `SessionEditorViewModel`) share a skeleton (a `Base` of new / gone / stored, the form mirrored into `SavedStateHandle`, `showErrors`, `saving`, the same guard in `save()`). A shared base class would hide four different save paths (the vessel's photo, the session's „in the future" refusal, the recipe's limits) behind one abstraction for about 40 lines; the vessel's form is saved field by field because it is not `Serializable`. Not proposed.
- **`CollectionSegmentMemory.None`, the `Placeholder*` screens, `NoCatalogReset`, `TestSettingsScreens`' defaults:** test seams (R8 lists some), kept as the other audits kept theirs.
- **`ActiveBrewBar`'s two layouts** (`ActiveBrewBarContent`, `BarHalfContent`): the same colour choice in two lines each; merging them would change which `Surface` carries the click and the semantics. Style-level.
- **`RatingCycle.valueText`, `TasteRadarShape.valueText`, `ratingText`, `averageRatingText`:** four number formats that look alike but round differently on purpose (halves, tenths, one decimal, `HALF_UP` of an average).
- **`GermanFormat`'s `NumberFormat` per call:** a cached instance is not thread-safe; the cost is negligible.
- **`StatsViewModel.choice` and `range`** (`StatsViewModel.kt:104–128`) read the same settings twice; `range` is the narrower key so the figures do not recompute when a fold changes. Kept.
- **The recipe editor's `PreAlertChoices`** (`RecipeLabels.kt`) and the steps sheet's `PreAlertOptions` (`StepPreAlertSelector.kt:45`): the same list of 5–30 s, but each maps to its own strings (the recipe has „Wie in Einstellungen"); sharing the list alone saves one line.
- **The two `vesselLabel` functions** (`BrewSetupScreen.kt:410`, `RecipeLabels.kt:42`): the same idea on two different models (`VesselOption` with a precomputed flag, `Vessel` with the regex) and two strings; joining them changes a model. Left.
- **`SettingsRoute`'s `DisposableEffect` and `SettingsViewModel.onCleared`** both stop the test alert and the preview: the first covers leaving the screen while the view model lives on in the back stack. Not a duplicate.
- **The stats charts** (`ChartFrame`, `ChartMotion`, `SortenDonut`, `RatingLineChart`): drawing and motion code pinned by goldens and motion tests; read by structure, and any change there risks a motion value (03 §3.6). Out by scope.
- **Style points left out:** the two `FilterChip`s with the same check icon in `BrewSetupScreen.kt:313–335`, the `DeleteDialog` / `SearchField` / `Section` / `Header` namesakes (different bodies), the long parameter lists of the tab hosts.
