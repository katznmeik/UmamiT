## Step 1: mechanical evidence (#297, D-120 Q3)

- **R8 usage:** `assembleRelease` with a local `-printusage <build dir>/r8-usage.txt` rule, reverted before any commit. Keep only `com.umamit.*` entries.
- **Lint:** `UnusedResources` and `UnusedIds` turned on by a local override, not by `config/lint/lint.xml`.
- **Dependencies:** a throwaway init script in `~/.gradle/init.d/` applies `com.autonomousapps.dependency-analysis` to the root project; `./gradlew buildHealth`. It sits beside the mirror init script (PROJECT_STATE „Environment") and must take the plugin from the mirror too.
- **Largest files** and **duplicated test fixtures** by script (`wc -l`, class-name grep).
- **Baseline:** the goldens' SHA-256 list, the files of `core/database/schemas/`, the DataStore key names in `core:datastore` main next to 05 §6, the commit. All of it goes into `docs/plans/v0.7.2-evidence.md`.

## Step 2: audits (#298, #300–#302, D-120 Q2)

- **Findings file per group:** `docs/plans/v0.7.2-audit-<group>.md` (`catalog`, `data`, `timer`, `ui`), one table: ID, place (file:line), kind (delete / simplify / restructure), risk, size, evidence, „pick?". About the top 15, no style points.
- **Tests** are read only where main code goes or step 1 shows duplicated fixtures.
- **Out of scope for findings:** anything that would change a golden, a schema, a DataStore key, a user-visible string, a motion value (03 §3.6) or the network rules (rule 7).
- After the catalog audit the session asks the PO #299 as options (keep / narrow / drop each of data, timer path, UI).

## Step 3: triage (#303, #304)

- The PO picks findings per group from options; „pick?" is filled in the audit files.
- Each picked restructuring: a decision, then its design at T4-F (#304) with the update of `06-architecture.md`, approved by the PO before #307/#308 start.

## Step 4: execution by risk (#305–#308)

- **Order:** #305 deletions → #306 local simplifications → #307 restructuring → #308 the timer path, **last and on its own** (nothing else in flight).
- **Parallelism:** at most 2 implementers at a time, each in its own worktree; one Gradle build at a time (`docs/plans/v0.4.0-resume.md` §3).
- **Timer-path fence:** until #308, the orchestrator checks after each ticket that `git diff main -- core/timer core/timer-engine feature/brew` is empty (plus the app's timer wiring files named in #301's audit).
- **A finding that turns out to change behaviour** (a golden, a test expectation, a key) is stopped and answered in its ticket, never worked around.

## Proof: no behaviour change

Checked by the orchestrator after each ticket and in full on the rc commit (#309):

1. **Goldens:** no `recordRoborazziDebug` in v0.7.2; `git diff main --stat -- '**/src/test/screenshots/**'` is empty and `verifyRoborazziDebug` passes.
2. **Room schemas:** `git diff main -- core/database/schemas` is empty, no database version changes; `scripts/check-frozen-schemas.sh` and `SchemaVersionsTest` pass.
3. **DataStore keys:** the key names in `core:datastore` main equal the #297 baseline; 05 §6 and the settings `schemaVersion` are unchanged.
4. **Timer tests (04 §12, rule 8):** unit and Robolectric tests of `core:timer-engine`, `core:timer` and `feature:brew` after each #308 step and on the rc commit; the CI emulator jobs (API 35, 36) on the PR.
5. **Accuracy (09 §4a):** all three variants (standard, alongside, two-brews) on the rc commit if #308 changed code, and always on the final's merge commit.
6. **Also:** `checkManifestPermissions` passes; no test is weakened (a test moves or goes only with the code it tests); `strings.xml` loses only unused entries.
