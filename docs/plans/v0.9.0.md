## Risk rules

- **Import path (T4):** #335 (reader) and #336 (safety copy, replace, undo).
  Their tests run before any UI uses them. The milestone review reads them
  at T4 (D-130 Q15). **#336 starts with a short design note** for the crash
  safety of 05 §8 „Replace" (D-130 item 26: how a committed Room
  transaction is recognised after a crash, roll forward or back), recorded
  as a D-130 build note before the code; a crash test per phase. Every refusal test asserts the database, `photos/` and
  `settings.json` are unchanged.
- **No timer code (D-130 Q16):** after **every** ticket the orchestrator
  checks that `git diff <before> -- feature/brew core/timer core/timer-engine`
  is empty. If a ticket must touch them, it stops and the PO is asked
  (that would bring back the T4 timer review and the accuracy runs).
  #336 reads `active_brew` only through its existing DAO; it never writes
  it except by the replace (which runs only when it is empty).
- **No migration:** umamit.db stays v9; `check-frozen-schemas.sh` and
  `SchemaVersionsTest` must pass unchanged. The settings get new keys only
  (a missing key reads its default, 05 §6), no settings `schemaVersion` step.
- **Manifest:** #341 adds the `FileProvider`, #342 `ReceiveRecipeActivity`;
  `checkManifestPermissions` must pass **unchanged** (no permission). A
  `ShareTargetTest`-style manifest test covers both.
- **Network (rule 7):** #342's *Tee über Shop-Link laden* reuses the CAT-17
  path unchanged (validator, polite session, stops). A fake HTTP client
  asserts zero requests on opening a file.
- **Public repository (rule 3):** all test files (backups, recipe files,
  CSV goldens) are synthetic and generated or hand-written; no shop text,
  photos or HTML.

   schema rules above).

   UI tickets) and the cross-module check `spotlessCheck :app:assembleDebug

   included). The orchestrator checks its result before the next merge
   builds on that head and fixes red at once.
