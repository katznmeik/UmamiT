## Process (as in v0.3.0)

- **PR:** one PR from `claude/umamit-m1-start-k0jg3n` into `main`, a draft while tickets are open, using `.github/pull_request_template.md`.
- **Implementers:** subagents in worktrees, with `model` and `effort` per tier (CLAUDE.md rule 5). Brief them with pointers (ticket, spec sections, D-100), not copies. Escalate one tier after a failure.
- **Before merging a ticket:** verify it yourself on the combined tree with the gate below and read the diff. A subagent's report is not proof.
- **Tests per seam (D-100, #145):** seam 1 data (in-memory Room plus pure JVM), seam 2 screens (ViewModel plus Compose under Robolectric, Roborazzi goldens light and dark, font 2.0 and a short screen), seam 3 app routes (Robolectric). Synthetic data only (D-016). The 04 §12 timer tests stay green.
- **UI tickets:** `/review-animations` on the new screens; washi/matcha and Cormorant Garamond as in `docs/design/mockup-v2-*.png` and 03; TalkBack labels on rows, chips, drag handles and stars; every string in `strings.xml`.
- **Code review at the end:** T3 for the data semantics, the setup, the session page and the test waits, T2 for the rest; fix or answer every finding.
- **Reporting:** push notifications only when the PO must act (rc ready, a blocking question). Questions go to the PO as selectable options.

## Local gate

As for v0.3.0, in sequential parts:

```bash
export ANDROID_HOME=${ANDROID_HOME:-/opt/android-sdk}
./gradlew spotlessCheck detekt checkManifestPermissions
./gradlew --max-workers=1 testDebugUnitTest
./gradlew --max-workers=1 lint
./gradlew --max-workers=1 verifyRoborazziDebug
./gradlew assembleDebugAndroidTest
```

- **A part killed for memory** (exit 137) is not a test failure: rerun that part alone.
- **One Gradle build at a time** across the orchestrator and the implementers: every Gradle command goes through the machine-wide `flock` and Kotlin compiles in-process (`~/.gradle/gradle.properties`, since v0.3.0). An implementer waits rather than start a second build.
- **Stopping Gradle:** never use `pkill java`, which kills every daemon including the agents'. Stop your own daemon with `./gradlew --stop`.
- **Robolectric's runtime jar** is fetched at test time, and a network hiccup has failed CI twice. Rerun once and comment on the PR.

## Guards that bite in this release

- **No migration:** `umamit.db` stays at v4; v1–v4 and `catalog.db` v1 are frozen by the `v*` tags (`scripts/check-frozen-schemas.sh` compares bytes). A ticket that thinks it needs a column stops and asks.
- **Rule 8:** the timer engine and controller are not changed (-15 excepted: session completion, at T4). Edits to teas, recipes and vessels never reach a running session; a tea or vessel of the active brew can't be archived or deleted.
- **Features don't depend on each other** (06 §3): shared pieces go to `core:ui` (-03); the app wires the routes.
- **Public repository:** no Tee-Kontor texts or photos in fixtures, goldens or renders; descriptions in tests and renders are synthetic (D-016).
- **Manifest:** no new permission (the photo picker is v0.4.1); `checkManifestPermissions` stays unchanged.
- **Accuracy run, both variants:** -12 changes timer test code, so the rc that carries it and the final release need a PASS of the standard run **and** `alongside` on their commit (full SHA, `api-level` 36, `steps` 50, `inject-delay-ms` 0; about 1 h each). Targets p95 ≤ 250 ms and max ≤ 1000 ms (09 §4a, D-073). Other rcs need it only when they touch timer code.
- **No downgrades:** going back to v0.3.0 needs an uninstall.
